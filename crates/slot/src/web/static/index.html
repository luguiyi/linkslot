linkSlot mods 管理 API（内部）

        
以下是 linkSlot 自己的管理页使用的 /api/mods/** 接口，普通 mod 作者不需要直接调用；mod 自带页面请使用上方文档中的 LinkSlotMod.request bridge。

        
    
          
  • GET /api/modsmod 列表：版本、作者、动作数、启用状态、category 分类、是否有管理页面、运行支持标记
    • 
          
  • GET /api/mods/item?id=mod 详情、版本与动作摘要
    • 
          
  • GET /api/mods/files?id=当前 mod 的只读目录树
    • 
          
  • GET/POST /api/mods/filemod bridge 的文本文件读取/保存
    • 
          
  • GET /mod-ui/<id>/web/*sandbox 中的 mod 自带管理页面
    • 
          
  • POST /api/mods/item新建 / 保存 mod 名称、版本与总开关
    • 
          
  • POST /api/mods/toggle启用 / 停用 mod
    • 
          
  • POST /api/mods/delete移动到 mods/.trash/
    • 
          
  • POST /api/mods/uninstall永久卸载 mod 及其全部动作
    • 
          
  • GET /api/mods/action?id=&action=动作源码与 revision
    • 
          
  • POST /api/mods/action新建 / 保存动作
    • 
          
  • POST /api/mods/action/toggle启用 / 停用动作
    • 
          
  • POST /api/mods/action/delete删除动作到 mod 回收站
    • 
          
  • POST /api/mods/testlinkSlot mods test --profile
    • 
          
  • POST /api/mods/checklinkSlot mods check --id [--action]
    • 
          
  • POST /api/files/upload?path=原始字节上传；导入 mod 的图片、字体、主题文件走这里
    • 
          
  • POST /api/files/mkdir创建目录；导入 mod 前先建 web/ 等子目录
    • 
          
  • GET /api/status设备是否可写、当前阶段等基础状态
    • 
        

        
所有写接口都需要页面发送的 X-Slot-Web: 1 请求头；设备游戏中或同步中时写入返回 409。内置动作编辑器已移除，动作由 mod 自带管理页面通过受限 bridge 管理。

        AI 开发提示词（复制给任意 AI）
        
先复制下面整段，再补一句你的需求，例如“做一个按游戏备份电池存档到 NAS 的 manual mod”。AI 应按提示词输出完整文件，而不是只给片段。

        
你是 linkSlot（Anbernic H700 掌机）的 Lua mod 开发者。请为 linkSlot v0.0.32 / mods API v1 编写一个可直接安装的 mod。
只使用本提示词列出的 API，不要假设存在 os、io、require、package、debug、任意 socket 或系统命令，也不要访问 Config/、主同步区或其它 mod 的文件。

【输出要求】
1. 先输出完整文件树，然后逐个文件给出完整内容，不要只给 diff 或片段。
2. 必须包含：mod.json、actions/<action-id>/action.json、actions/<action-id>/main.lua、web/index.html、web/app.js、README.md；可选 config.json、web/style.css。
3. 代码使用 Lua 5.4 语法；Web 页面只使用原生 HTML/CSS/JS，不加载 CDN、外部字体或第三方脚本。
4. 如果需求缺少关键信息（服务地址、API 格式、同步方向、冲突策略），先列出问题再等待，不要编造。
5. 文件路径中的 <id> 只能使用小写字母、数字、_、-；mod id 与 action id 分开。

【目录结构】
mods/<mod-id>/
  mod.json
  config.json                  # 可选，linkSlot 不解释，mod 自己读写
  README.md
  actions/<action-id>/
    action.json
    main.lua
  web/
    index.html                 # 必需；社区用户从 Web 打开管理页
    app.js
    style.css

【mod.json（schema 2）】
{"schema":2,"name":"显示名称","version":"1.0.0","author":"你的名字","enabled":false}
enabled 是总开关，建议发布时 false，由用户在设备/Web 启用。

【action.json（schema 1）】
{"schema":1,"name":"动作名称","timing":"manual","enabled":true,"order":100,"boot_delay_minutes":0}
timing 只能是：
before_upload / after_upload / before_download / after_download / after_sync / after_boot / manual
after_boot 在设备启动后执行；boot_delay_minutes 是 0..=1440 的整数（分钟），只对 after_boot 有意义。同一系统启动内只执行一次；没有 ctx.game，ctx.unit 为 "boot"；不要用 mods.report/mods.choose。
manual 不参与云同步：存在启用的 manual 动作时，卡带界面长按 Y 执行 linkSlot mods run。
manual 动作可选 ui 复用云同步动画语法：
"ui":{"animation":"cloud_sync","title":"同步电池存档","units":["sav"],"show_cloud":true,"direction":"upload"}
animation 目前只支持 cloud_sync；units 只支持 state/sav，空数组显示通用网络数据流；direction 可选 upload/download；没有 ui 的 manual 动作仍显示简洁暗幕和阶段文字。
order 为整数，越小越先执行。

【Lua 可用 API】
ctx.api = 1
ctx.timing / ctx.unit（state|sav|boot）/ ctx.unit_path
ctx.game = {name, platform, core, rom_sha256, state_dir, sav_path, srm_path}；after_sync / after_boot 时 ctx.game 为 nil
ctx.mod = {id, dir, config, config_error}
ctx.action = {id, name, dir}
ctx.choices = 已确定的 mods.choose 答案
ctx.webdav = {active, profiles={{id,name,remote_root}, ...}}
ctx.transfer = 仅 after_upload/after_download：{direction,result,version}

files.read(rel) -> string|nil；files.write(rel,data) -> true；files.list(rel) -> 数组；files.stat(rel) -> table|nil；files.exists(rel) -> boolean；files.mkdir(rel) -> true
只能访问 States/、Saves/ 和当前 mods/<mod-id>/；States 只允许 .state/.png，Saves 只允许 .sav/.srm；写入是原子的。

webdav.get([profile,] path) -> string|nil；webdav.put([profile,] path,data)；webdav.put_atomic([profile,] path,data)；webdav.list([profile,] path) -> 数组|nil；webdav.stat([profile,] path) -> table|nil；webdav.mkdir([profile,] path)
profile 省略时使用 ctx.webdav.active；只能访问该同步方式的 remote_root。

http.get(segments[,query]) -> {status,body}；http.post(segments,body,content_type[,query])；http.request(method,segments,opts)
只能访问当前 mod config.json 的 base_url 来源；method 仅 GET/POST/PUT；不跟随重定向；404 不返回 nil，必须判断 status。
http.request 的 opts 支持 body / content_type / query / headers；headers 是字符串表，例如 {["Authorization"]="Bearer ..."}。Host、Content-Length、Connection、Transfer-Encoding 不允许覆盖。

library.exists("intro"|"guide") -> bool；library.write("intro"|"guide", text) -> true
仅 manual 动作可用；只写当前游戏的 Labels/<平台>/<游戏>.txt 和 Guides/<平台>/<游戏>.txt，不能写别的路径。

json.encode(v) / json.decode(text)
hash.sha256(data) / hash.sha256_file(rel)
zip.list(data) / zip.read(data,index_or_name) / zip.build({{name=,data=},...})
log.info/warn/error/debug；print(...) 写入日志

mods.report{status="ok"|"noop"|"error", direction="upload"|"download", error="net"|"config"|"server"|"fs"|"verify"|"timeout", detail="单行中文"}
mods.choose{key,title,body,options={{id,label},...},default} -> 已选 id
ui.confirm{title,body,yes,no} -> boolean（manual；B=否）
ui.message{title,body,button} -> true（manual；单按钮文字弹窗）
mods.progress{value=0..1,label} 或 {current,total,label}：manual 动画进度条；不上报则扫光
两者复用 choice 检查点：首次中止并弹窗，恢复后返回结果；不要用 pcall 包住。
mods.choose 只用于 manual；首次运行会中止并请求设备弹窗，恢复后返回选择。不要在它之前写文件，不要用 pcall 包住它。

【mod 自带 Web 管理页】
web/index.html 必须引用 /mod-ui/sdk.js，然后使用：
window.LinkSlotMod.ready.then(info => ...)
LinkSlotMod.request("files.read", {path:"config.json"})
可用 bridge：
files.list {} / files.read {path} / files.write {path,content,revision?}
actions.list {} / actions.get {action} / actions.save {action_id?,name,timing,enabled,order,boot_delay_minutes?,content,revision?} / actions.toggle {action,enabled} / actions.delete {action} / actions.check {action?}
context.saves {} / context.storages {}
bridge 只能访问当前 mod；页面不能直接访问 /api/** 或任意网络。config.json 由 mod 页面通过 files.write 保存。

【限制】
单脚本 15 秒（manual 90 秒）、Lua 内存 32 MiB、manual 长按 Y 只执行一个动作；日志 200 行；本地读 64 MiB / 写 32 MiB；远程普通时机 16 请求/64 MiB，after_sync 64/128 MiB；http 16/64 MiB；zip 输入 16 MiB、单条解压 32 MiB、总量 64 MiB；网络超时普通 min(sync.timeout_secs,10) 秒，manual 最高 60 秒。

请先确认需求，再按上述结构输出完整实现。

        2. Lua 动作 API
        
下面是最常用的完整速查；字段省略规则、错误分类和完整示例见 workdoc/lua-mod-api-v1.md。

        
-- 上下文（只读全局 ctx）
ctx.api                 -- 1
ctx.timing              -- before_upload / after_upload / before_download / after_download / after_sync / after_boot / manual
ctx.unit                -- state / sav / boot；after_sync 为 nil；manual 为 sav；after_boot 为 boot
ctx.unit_path           -- state=目录；sav=现有 .sav/.srm；after_sync / after_boot=nil
ctx.game                -- {name, platform, core, rom_sha256, state_dir, sav_path, srm_path}；after_sync / after_boot 为 nil
ctx.mod.id / ctx.mod.dir
ctx.mod.config          -- 当前 mod config.json 解析结果（不存在为 nil）
ctx.mod.config_error    -- config.json 读取/解析错误（无错误为 nil）
ctx.action.id / ctx.action.name / ctx.action.dir
ctx.choices             -- { key = option }，已确定的 mods.choose 答案
ctx.webdav.active       -- 当前同步方式 id；没有兼容根时为 nil
ctx.webdav.profiles     -- { id, name, remote_root } 数组
ctx.transfer            -- after_upload/after_download：{ direction, result, version }

-- 本地文件（相对卡根；只允许 States/、Saves/、当前 mods/<id>/）
files.read(rel)         -- string 或 nil
files.write(rel, data)  -- true；States 只允许 .state/.png，Saves 只允许 .sav/.srm
files.list(rel)         -- { name, is_dir, size, mtime } 数组
files.stat(rel)         -- { name, is_dir, size, mtime } 或 nil
files.exists(rel)       -- boolean
files.mkdir(rel)        -- true

-- 当前游戏资料（仅 timing=manual；不影响 ROM/存档/数据库）
library.exists("intro"|"guide")       -- boolean
library.write("intro"|"guide", text)  -- true，写入 Labels/Guides 的约定路径

-- 兼容根（省略 profile = ctx.webdav.active）
webdav.get([profile,] path)         -- string 或 nil（404）
webdav.put([profile,] path, data)
webdav.put_atomic([profile,] path, data)
webdav.list([profile,] path)        -- { name, is_dir, size, modified } 或 nil
webdav.stat([profile,] path)        -- 条目或 nil
webdav.mkdir([profile,] path)

-- 受控 HTTP：只能访问本 mod config.json 的 base_url 来源
http.get(segments [, query])                    -- { status, body }
http.post(segments, body, content_type [, query])
http.request(method, segments, opts)            -- GET/POST/PUT；opts: body/content_type/query/headers

-- 手动动作结果（仅 timing=manual）
mods.report{ status="ok"|"noop"|"error", direction="upload"|"download",
             error="net"|"config"|"server"|"fs"|"verify"|"timeout",
             detail="单行中文" }

-- 通用选择弹窗（仅 timing=manual；A 确认 / B 取消）
local choice = mods.choose{
  key="conflict", title="存档冲突" data-i18n-title="web.sync.conflictTitle", body="本地和 GBAStation 都改过",
  default="remote",
  options={
    { id="remote", label="用 GBAStation 覆盖本地" },
    { id="local",  label="用本地覆盖 GBAStation" },
  },
}

-- 辅助
json.encode(v) / json.decode(text)
hash.sha256(data) / hash.sha256_file(rel)
zip.list(data) / zip.read(data, index_or_name) / zip.build({ {name=, data=}, ... })
log.info / log.warn / log.error / log.debug
print(...)              -- 写入日志，不写 stdout

      


      

        3. mod 自带 Web 管理页（bridge）
        
页面在 sandbox iframe 中运行，不能直接访问 /api/**；先加载 SDK，再通过受限 bridge 操作当前 mod。

        
// web/index.html
<script src="/mod-ui/sdk.js"></script>
<script src="app.js"></script>

// web/app.js
LinkSlotMod.ready.then(function (info) {
  // info = { id, name, version }
  return LinkSlotMod.request("files.read", { path: "config.json" });
}).then(function (file) {
  // file = { path, content, revision, editable, size }
});

LinkSlotMod.request("actions.list") // { actions: [...] }
LinkSlotMod.request("actions.save", {
  action_id: "sync", name: "同步", timing: "manual",
  enabled: true, order: 100, boot_delay_minutes: 0, content: luaSource
});

        

          

            
bridge 方法参数返回 / 说明

            
              
files.list{}当前 mod 的只读文件树。

              
files.read{path}{path, content, revision, editable, size}

              
files.write{path, content, revision?}原子写；revision 用于避免覆盖其它页面修改。

              
actions.list{}{ actions: [...] }

              
actions.get{action}动作详情与 Lua 源码。

              
actions.save{action_id?,name,timing,enabled,order,boot_delay_minutes?,content,revision?}新建或保存动作；不传 action_id 表示新建。after_boot 时 boot_delay_minutes 为 0..=1440。

              
actions.toggle{action, enabled}启用/停用单个动作。

              
actions.delete{action}移动到 mod 回收站。

              
actions.check{action?}调用 linkSlot CLI 做 Lua 语法检查。

              
context.saves{}当前存档/游戏列表，只读。

              
context.storages{}{ storages, timings }，只读。

              
tianma.start{path, overwrite?}启动天马G 信息导入（主程序后台任务，只写 Labels/GBA）。

              
tianma.status{}导入进度、匹配/导入/跳过数量和错误。

              
tianma.cancel{}请求取消当前导入任务。

              
gbastation.games{base_url}读取 GBAStation 游戏列表，不下载 ROM；仅 gbastation-rom-sync 可调用。

              
gbastation.start{base_url, keys, overwrite?}下载选中 ROM 到 Games/<平台>/。

              
gbastation.status{}导入进度、数量、当前游戏和错误。

              
gbastation.cancel{}请求取消 GBAStation ROM 导入。

            
          

        

        
所有 bridge 调用只作用于当前 mod；页面无法读取其它 mod 或直接发网络请求。天马导入的 tianma.* 是主程序提供的受控例外，只读写 Imports/ 和 Labels/GBA/。GBAStation 的 gbastation.* 也只允许 gbastation-rom-sync 调用，并且只写对应的 Games/ 目录。

      


      

        4. 示例：manual + HTTP / 冲突选择
        
-- actions/sync/main.lua（manual）
local base = ctx.mod.config and ctx.mod.config.base_url
if not base then
  mods.report{ status="error", error="config", detail="请先在管理页填写服务地址" }
  return
end

local response = http.get({"api", "saves"}, { game = ctx.game.name })
if response.status ~= 200 then
  mods.report{ status="error", error="server",
               detail="服务返回 HTTP " .. tostring(response.status) }
  return
end

local choice = mods.choose{
  key = "conflict",

        主题包（配色 / 壁纸 / 字体 / 铭牌 / 芯片封面）
        
一个 mod 只要带下列任意一个文件，就会被当作主题包；全部在启动时读取，改动需要重启生效。关闭或卸载后重启即回到内置外观，不会改写 Config/theme.txt。

        

          

            
文件作用说明

            
              
theme.txt配色键名与 Config/theme.txt 一致：preset、housing、recess、opening、edge、bg、bg_top、surface、surface_border、selected、selected_border、ink、ink_selected、ink_dim、accent、accent_dim

              
wallpaper.png壁纸替代 Wallpapers/ 的随机壁纸，按 720×480 铺满裁切

              
font.otf / font.ttf / font.ttc字体需含中文字形；解析失败会记录日志并回退内置字体

              
slot_back_gba/gb/gbc/fc.png卡槽铭牌缺省时用内置刻字铭牌；存储卡里的 System/Carts/slot_back_*.png 优先级更高

              
sync-chip.png芯片封面只填充封装内部，引脚、外框、Pin 1、状态灯仍由系统绘制

            
          

        

        
优先级：主题 mod（已启用、order 最小）→ Config/theme.txt → 内置预设。多个主题 mod 同时启用时，只有 order 最小的那个生效。

        
// mods/<id>/theme.txt
preset default
bg      #121212
surface #242424
ink     #e6e6e6
accent  #cfcfcf

// mod.json 里声明分类，Web 列表归到「外观」
{
  "schema": 2,
  "name": "我的主题",
  "version": "1.0.0",
  "category": "theme"
}

        
字体和铭牌属于第三方素材，请自行确认授权：字体建议 SIL OFL，机种字标请勿随包分发未获授权的商标素材。

      




        5. 限制、安全与排障
        

          

            
项目限制 / 行为

            
              
单脚本15 秒（manual 90 秒）、32 MiB Lua 内存、200 行日志。

              
manual 动作单脚本 90 秒；长按 Y 只执行优先级最高的一个动作，失败则整体失败。

              
本地文件读 64 MiB / 写 32 MiB；只能 States/、Saves/、当前 mod 目录；manual 另有当前游戏的 library 资料写入。

              
WebDAV普通时机 16 次/64 MiB；after_sync 64 次/128 MiB；超时取 sync.timeout_secs 与 10 秒的较小值。

              
HTTP仅 base_url 来源；16 次/64 MiB；普通时机超时取 sync.timeout_secs 与 10 秒的较小值，manual 最高 60 秒；不跟随重定向；404 也要判断 status。

              
ZIP输入 16 MiB、256 条、单条解压 32 MiB、总量 64 MiB。

              
安全边界不能访问 Config/、主同步区、其它 mod、系统命令或任意 URL；只启用可信 mod。

            
          

        

        
长按 Y 没有执行 manual：确认 mod 总开关、动作开关、timing=manual 均启用，并用 linkSlot mods check --id <id> --action <action> 检查语法。页面打不开：确认存在 web/index.html 且已安装到 mods/<id>/。

      

    


    

      

        
Mod development docs API v1

        Mod package and lifecycle
        

          
The default package path is mods/<id>/. The id comes from the folder name; mod.json is required.

          
mods/my-mod/
  mod.json              # required
  config.json           # optional, owned by the mod
  README.md             # optional description
  actions/sync/main.lua # one Lua entry per action
  web/index.html        # optional sandboxed mod UI
  web/app.js            # optional assets for that UI

          
Import through Mods → Import mod ZIP. A ZIP is expected to contain mods/<id>/ or the mod folder itself. Keep the mod off while editing files; enable it again after a syntax check.

        

      


      

        mod.json
        

          
{
  "schema": 2,
  "name": "Example mod",
  "version": "1.0.0",
  "author": "you",
  "enabled": false
}

          
Schema 2 is current. Actions are discovered from actions/<action_id>/main.lua; timing is one of manual, before_upload, after_upload, before_download, after_download, after_sync or after_boot.

          
Set "web": true when web/index.html exists. The page runs in a sandboxed iframe with an opaque origin and may only call the host bridge.

        

      


      

        Lua script contract
        

          
Each action is a plain Lua file evaluated in an isolated runtime. The host provides one global ctx and the modules below; no other globals are available.

          
-- actions/sync/main.lua
local base = ctx.mod.config and ctx.mod.config.base_url
if not base then
  mods.report{ level = "warn", message = "base_url is not configured" }
  return
end
ctx.http.get(base .. "/index.json")
ctx.files.write("cache/index.json", ctx.http.body())
mods.report{ message = "sync finished" }

          
ctx exposes ctx.mod (id, name, version, enabled, config, data dir), ctx.timing, ctx.game (when the host has a current game), ctx.args and ctx.run. mods.report writes a user-visible status line; mods.fail ends the action.

        

      


      

        Runtime modules and limits
        

          

            
ModuleWhat it may do

            
              
ctx.filesRead 64 MiB, write 32 MiB, only States/, Saves/ and this mod's data directory; manual timing may also write the current game's library metadata.

              
ctx.webdav16 requests / 64 MiB normally; 64 requests / 128 MiB after sync; timeout is the smaller of sync.timeout_secs and 10 seconds.

              
ctx.httpOnly the configured base_url origin; 16 requests / 64 MiB; manual timing may use up to 60 seconds; redirects are not followed; check the status even on 404.

              
ctx.zipInput 16 MiB, 256 entries, 32 MiB per entry, 64 MiB total output.

            
          

          
Mods cannot read Config/, the main sync area, other mods, run system commands or open arbitrary URLs. Only install mods you trust.

        

      


      

        Web UI bridge
        

          
A mod page is served from /mod-ui/<id>/web/index.html inside an iframe with sandbox="allow-scripts". It never gets the page's cookies or direct /api access; it uses the injected SDK.

          
<script src="/mod-ui/sdk.js"></script>
<script>
LinkSlotMod.ready.then(function (info) {
  // info.locale is "zh-CN" or "en-US"
  return LinkSlotMod.request('files.read', { path: 'config.json' });
}).then(function (file) {
  console.log(file.content);
});
</script>

          
Requests: files.read, files.write, files.list, files.remove, actions.read, actions.write, actions.delete, library.migrateSidecars, and the read-only query methods listed under the management API. The host checks every request against the current mod id.
