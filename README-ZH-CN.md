# Slot 中文定制版：云同步、网络设置与 Web 管理

发布版本：v0.9.9（已构建）。

## 语言（v0.9.9）
设备端、Web 管理页、浏览器游玩页和自带 mod 支持中文 / English。在掌机
「系统设置 → 语言」或 Web 设置页切换，选择会写入 `linkSlot/Config/language.txt`；
设备、网页和 mod 读取同一个文件。语言菜单里的「中文」保持中文名称。

## 安装
关机后备份卡内 System/slot、Config 和存档。解压对应的 h700 发布包，将包内文件夹里的内容合并到卡根目录，替换同名文件。不要在卡内再套一层目录。

完成后根目录应有 System、Cheats、Games 等目录。安装包已包含配好的金手指，不必再复制原始大全。ROM、Labels、存档和 linkSlot/Config/slot.state 不在覆盖范围内。

### 卡带外观与插槽蚀刻

- GBA / GB / GBC / FC 的卡面都改用参考项目的整卡 PNG 美术：GBA 360×202，GB/GBC 240×276，FC 360×241；
- 美术内置在 `System/slot` 中，不要求用户另放 `System/linkSlot/assets/carts/cart_*.png`；
- 标签窗口仍按各卡面实测区域粘贴封面，透明处露出参考项目的纸面/塑料；
- 版本包不再带任何 `System/linkSlot/assets/carts/slot_back_*.png`；所有卡槽（GBA / GB / GBC / FC / SFC / 最近游玩 / 收藏）默认使用内置的大字号蚀刻字标，玩家可自备同名 PNG 覆盖。

### ROM 内容 ID（v0.5.0 起，联机统一 v0.6.0 起）

- 每个 ROM 的完整字节计算 SHA-256，并使用 `平台 + SHA-256` 作为内容 ID、联机身份和传输身份；
- 合集/单游戏导入会实际读取 ZIP 内的 ROM 计算 SHA-256，而不是只信任清单；
- 相同内容的 ROM 已存在时会跳过 ROM 及对应资源，不再生成第二张卡带；
- 导入包清单 v2 会记录每个 ROM 的 SHA-256；v1 旧包仍可导入，并按实际字节计算；
- 路径仍是文件定位与主键，SHA-256 是逻辑内容身份；不同区域/修订/补丁版本会得到不同内容 ID；
- 联机与卡带传输不再使用 FNV；旧版联机协议不兼容。

### TXT / EPUB 游戏攻略（v0.4.8 起，EPUB v0.4.14 起）

- 攻略放在 `Guides/<平台>/<游戏名>.txt` 或 `.epub`，也可由游戏元数据指定其他路径；
- Web 游戏详情页可填写路径，或直接上传 TXT / EPUB；
- EPUB 会按 OPF 的 spine 顺序提取正文和图片；图片单独成页并等比缩放到屏幕内，脚本和样式忽略；
- 游戏菜单固定显示「查看攻略」；没有攻略时点击会打开「暂无攻略」弹窗，提示 Web 上传或 AI mod 生成；
- 阅读页支持上下/L/R 翻页，B 返回游戏菜单；
- 自动识别 UTF-8 和常见 GBK 中文 TXT；
- 单个游戏导出/导入会一并携带攻略和 `guide` 元数据。

### Web 系统升级清单（v0.4.10 起）

Web 的「系统升级」会同时替换 `System/**` 和 `linkSlot/version.json`。升级后版本清单应与实际二进制一致。

- 0.4.8 及更早版本的 Web 升级只替换 `System/**`，不会更新 `version.json`；
- 从 0.4.9 开始修复；
- 如果从 0.4.8 通过 Web 升到 0.4.9，升级完成后需要再手动把 0.4.9 包里的 `version.json` 复制到卡根一次。

### 大库启动扫描（v0.4.7 起）

- 扫描不再长期保留 `DirEntry`，避免数千个 ROM 时目录描述符耗尽；
- 同一 `Labels/` 子目录只列举一次，不再每个 ROM 重复 `read_dir`；
- 4314 个 ROM 的本机模拟热启动约 0.25 秒，首次建库约 4.8 秒（不含实际 SD 卡速度）。

### 启动性能（v0.3.26 起）

v0.3.26 起元数据写入 SQLite，启动时一次读取全部行；不再为哈希索引逐卡重写 JSON sidecar，也不再维护 library.cache.json。

### 卡带传输模式（v0.2.16 起）

`M → 网络设置 → 卡带传输模式`，两台掌机按联机方式匹配（一台「创建匹配」、一台「加入匹配」）。

- 匹配成功后双方进入卡带架，可用左右方向键在卡带间移动，`L1`/`R1` 切换平台；在卡带架按 `M` 会弹窗确认是否退出传输模式；
- 一方选中一张卡（A）发出传输请求，另一方收到「接收这张卡？」确认；
- 接收方在卡带真正落盘前显示一张同平台、同壳色的空白卡带预览，带当前游戏标题（如「阿拉丁」）但不带发送方封面；卡带插入和传输动画都使用这张预览卡；
- 选中卡带时使用与开始游戏相同的插卡动画；卡带插好后一直留在槽里，直到传输完成；接收方确认后同样插卡并保持；
- 对方拒绝、对方已有同一 ROM、传输失败或传输完成时，使用游戏退出时的拔卡动画把卡带弹出；对方已有同一 ROM 时先完整播放插卡动画，再保持插入 1 秒后弹出；接收方判定重复后立即回到可再次接收的状态；
- 传输中卡带保持插入，界面保留大号百分比和 `ROM/封面/介绍/视频` 四个资产状态，百分比位于卡片上方的安全区域；百分比按面板实际字号直接栅格化，不再缩放小图导致模糊；标题、游戏名、存档说明、退出提示和方向箭头已移除，不再使用底部进度条；背景压暗但保留清晰卡槽；即使 FC 等小 ROM 传得很快，该界面也会至少显示 1 秒；
- 传输完成双方一起弹出卡带；接收方得到完整卡带：ROM、封面、介绍 TXT、演示视频、壳色/壳型都和发送方一致；接收方会自动切到新卡所在平台页并选中它，拔卡动画直接在当前页完成；
- **唯一不传输的是卡带存档**：电池存档、即时存档、resume 状态、倒带数据都不复制；
- 接收方同名卡已存在时自动使用「名字 (2)」等新名字，不覆盖旧卡；
- 接收方已有**同一个 ROM**（按 ROM 内容的哈希判断）时：
  - 如果对方卡片上的封面、介绍、视频本地都有，不开始传输：发送方卡带先完整插入、停 1 秒，再弹出，并提示「对方已拥有当前卡带」；接收方显示「本机已拥有当前卡带」；
  - 如果本机缺少其中某些资料，接收方先询问「补充『游戏名』资料？」，确认后只传缺失的封面/介绍/视频，不重传 ROM，也不覆盖本地已有资料；发送方和接收方的进度界面只列出实际传输的资料；
- 资料补全同样不传输电池存档、即时存档、resume 状态、倒带数据或壳色壳型；
- 查重直接使用开机后台预计算并写入 `linkSlot/Config/rom_hashes.tsv` 的本地哈希表，以及元数据数据库里经过 size/mtime 校验的哈希；传输成功后立即把新卡哈希写入数据库，下一次传输就能识别；传输时不会全局读取/哈希整个卡带库。

传输模式与游戏联机互不影响：退出传输模式会关闭热点和匹配，不会保留游戏房间。

### 单个游戏导出/导入（v0.4.6 起）

游戏详情页新增「导出此游戏」，生成的 ZIP 与合集共用导入入口：

- ROM；
- 封面、介绍、视频；
- 金手指 `.cht`；
- 电池存档 `.sav` / `.srm`；
- 所有核心的即时存档、缩略图和 `playtime.json`；
- 卡带元数据（颜色、壳型、标题、金手指路径等）。

工具栏「导入游戏/合集」同时接受平台合集和单个游戏包。导入单个游戏包会覆盖同名游戏的这些关联文件，操作前请备份。

### Mod 固定 ID（v0.4.5 起）

- `mod.json` 可以写 `"id": "gbastation-battery-sync"`；
- Web 导入优先使用 mod.json 的 id，缺省使用 ZIP 内 `mods/<id>` 目录名；
- 同一 ID 再次导入会原地升级，保留 mod 的 `state/` 和 `config.json`；
- 新 mod 仍可自动生成 ID，手动解压安装则始终使用目录名。

### Web 列表分批加载（v0.4.4 起）

Web 游戏库和存档页不再一次创建全部 DOM：

- 游戏库每批 40 个，滚动接近底部时自动加载下一批；
- 存档页每批 10 个单元，同样按滚动加载；
- 使用 `IntersectionObserver` 预加载，不支持时显示「加载更多」按钮；
- 搜索、平台筛选、刷新会重置分批列表。

### 快进与倒带（v0.4.2 起）

快进期间也会记录倒带快照，因此快进到 B 后按倒带，会从 B 附近的快照逐步往回走，而不是一步跳回快进开始前的 A。8 倍快进时快照间隔较粗，但不会再整段丢失。

### 默认北京时间（v0.4.12 起）

- 新设备默认时区为北京时间 `UTC+08:00`；
- 旧状态文件如果没有时区初始化标记，且 `utc_offset_min=0`，首次读取会迁移为 `+08:00`；
- 迁移后写入 `utc_offset_initialized=1`，之后手动设置 UTC+0 会被保留；
- 联网校时仍然只更新 UTC，显示时加上北京时间偏移。

### 联网自动校时（v0.4.1 起）

Wi-Fi 取得 IP 后，设备会在后台通过 SNTP 校时：

- 依次尝试 `pool.ntp.org`、`time.cloudflare.com`、`ntp.aliyun.com`；
- 使用 UDP 123，2 秒超时，不阻塞 UI；
- 只更新 UTC，保留用户设置的时区偏移；
- 成功显示「时间已联网同步」；
- 失败后每 10 分钟重试，成功后 6 小时内不重复校时；
- 联机、Web 服务和卡带传输不依赖该功能，校时失败不影响使用。

### 每游戏卡带元数据（v0.3.26 起使用 SQLite）

元数据的权威存储是：

```text
Metadata/library.db
```

SQLite 表 `carts` 每张 ROM 一行，记录：

- ROM 相对路径、平台、标题/代码；
- `hash`（FNV-1a，16 进制文本）、`size`、`mtime`；
- 封面、介绍 TXT、演示视频的相对路径；
- 金手指 `.cht` 的相对路径（留空时使用 `Cheats/<平台>/<核心>/<游戏名>.cht`）；
- 卡带颜色、壳型/材质、核心选择等。

原则：

- 数据库是每张卡的权威元数据；
- `Games/`、`Labels/` 里的文件仍是 ROM/资源本体；
- Web 游戏库的颜色、金手指路径、封面、介绍、视频和 ROM 替换只改数据库及对应资源文件；
- 不再读写 `Metadata/*.json`，也不再生成 `library.cache.json`；
- 旧 sidecar 不自动导入；需要旧数据迁移时由独立 mod/工具完成；
- 备份/迁移前应同时保存 `library.db`（以及运行中的 `-wal`/`-shm`）。

数据库使用 WAL 和单连接短事务；启动时一次读取全部行到内存，卡带架翻页不会逐卡查询 SQLite。

### 0.4.0 元数据迁移 mod

0.4.0 不自动读取旧 sidecar。需要迁移旧版 `Metadata/*.json` 时，使用独立 mod：

```text
linkslot-mod-metadata-migrate-v1.0.0.zip
```

安装后在 Web 的 mod 管理页打开「旧版元数据迁移」，先备份 `Metadata/`，再点「一键迁移」。迁移会写入 `Metadata/library.db`，不会删除旧 JSON。

### AI 游戏资料补全 mod（0.6.2 起）

`linkslot-mod-ai-game-info-v1.0.0.zip` 使用 DeepSeek 文本接口，为当前游戏补全介绍和攻略：

```text
Labels/<平台>/<游戏名>.txt   # 介绍
Guides/<平台>/<游戏名>.txt   # 攻略
```

- 卡带架长按 Y，选择「AI 游戏资料补全」；
- 第二次确认可只补介绍、只补攻略或两者都补；
- 默认只补缺失内容；Web mod 设置可开启覆盖；
- API Key 在 Web mod 管理页设置，模型固定使用 `deepseek-flash`；
- API Key 明文保存在 mod 的 `config.json`，不要分享；
- 只发送游戏名、平台、核心和 SHA-256，不上传 ROM；
- 第一版不生成封面，封面留给后续图像生成 mod；
- 需要设备已联网，目标程序 0.6.2+。

### Web 游戏详情（v0.3.20 起）

游戏详情增加「金手指文件」路径设置：

- 路径相对存储卡根目录，必须是已存在的 `.cht` 文件；
- 保存到该游戏数据库记录的 `cheat` 字段；
- 留空清除自定义路径，游戏内金手指菜单回退到默认 `Cheats/<平台>/<核心>/<游戏名>.cht`；
- 拒绝绝对路径、`..`、反斜杠和非 `.cht` 文件。

### Web 设置菜单与上传上限（v0.3.6 起）

Web 首页新增「设置」页，可设置单个上传文件的上限：

- 默认 **32 MB**；
- 可设置 **1–256 MB**；
- 适用于文件浏览器上传、ROM 替换、介绍视频上传和版本包上传；
- 上传时显示全局进度条和文件名，上传期间禁止重复触发；
- 保存后对新请求生效，已开始的请求不受影响。

设置保存在：

```text
linkSlot/Config/web.toml
```

页面会显示当前上限；服务端也会在 HTTP 层按同一上限拒绝过大的请求体。

### Web 修改卡带颜色（v0.2.13 起）

Web「游戏库」→ 点开游戏卡片 →「游戏详情」→「卡带颜色」：

- 用取色器或 `#rrggbb` 输入修改，点「保存颜色」立即写入卡内；
- 设备在游戏或同步中时，写操作按原有规则拒绝；
- 首次扫描到没有颜色的 ROM 时，会自动分配一个稳定的随机初始色，并写入 `linkSlot/Config/cart_color.txt`；
- 配置文件按平台区分，例如 `GBA/游戏名 = #rrggbb`，同一游戏名在 GBA 和 GB 下不会串色。

### FC 联机（v0.0.46 起）
两台 H700 各插**同一张** `.nes` 卡，其中一台进游戏后按 `SELECT + M` 选「创建联机」，另一台选「加入联机」，走的是与 GBA 联机相同的 WiFi 热点直连（不需要路由器）。

- 主机 = 1P，加入方 = 2P；两块屏幕显示**同一画面**——这就是「一台 Famicom 接两个手柄」，2P 游戏（魂斗罗、坦克大战等）都能双打。
- 开局时主机把自己的存档状态与电池存档发给对方，两边从同一个位置开始；之后每帧同步手柄输入（3 帧延迟，约 50ms）。
- 双方的游戏内容必须一致：机种/核心/ROM 哈希在连接时校验，不一致会直接提示「对方的游戏不一致」。
- 双方都需要 **v0.0.46 及以上**；联机中照旧禁用金手指、快进、倒带与云同步。

### 联机会话（v0.2.14 起）：主机房间跟着当前游戏走
联机入口只在**游戏内**：按 `SELECT + M`（或游戏菜单里的「联机」）选择「创建联机」或「加入联机」。卡带架 / 网络设置里不再提供联机入口。

- **主机创建一次就保持主机状态**：即使副机还没来、或者中途掉线，主机会继续在当前游戏里等待，不会退回未联机状态；
- **副机随时加入**：主机仍在当前游戏时，副机打开同一张卡、从游戏内选「加入联机」即可重新加入；
- **主机主动离开当前游戏**（退卡、回卡带架、关机、休眠等）才会结束房间；重新开始同一游戏会保留房间；
- 断线只关闭这一局的电缆：主机自动重新监听，副机可在游戏内重新加入；不会要求主机重新创建房间；
- 主机掉线后仍显示「主机 · 等待对方」，副机侧会结束旧连接，重新加入后恢复联机；
- 双方仍按机种、核心和 ROM 内容（哈希）校验；不一致会提示「对方的游戏不一致」；
- 设备名取自 `linkSlot/Config/device_name.txt`（不存在时用系统 hostname，最多 16 字节），在联机页显示为「对方：xxx」；
- 与旧版本互连时：若对方不发游戏通告帧，本机 1.5 秒后按原来的方式直接建立连接，不会卡住；
- **GBA / GB / GBC（mGBA）和 FC 使用同一套房间逻辑**；gpSP 的 netpacket 也沿用同一入口，但它不能传主机进度（联机页会写明）。

> 旧的「连一次、连续换好几张卡」会话已移除：联机现在只服务于当前游戏，避免从卡带架误开或误留房间。

FC 的其它边界：
- **暂不支持 `.fds`。** 只有 `.nes`。`.fds` 需要 `BIOS/disksys.rom` 与换面按键，本版未接。
- **只支持 1P/2P 标准手柄**（方向 + A/B + 选择/开始，X/Y 为连发 A/B）。4 人分插器与光枪需要外接手柄，本机没有入口。
FC 的即时存档、电池存档、快进、倒带、缩略图与其它机种走同一套路径：`States/FC/fceumm/<游戏名>/` 与 `Saves/FC/<游戏名>.sav`。
云同步也认识 FC：`linkSlot sync --platform FC --emulator fceumm --game <游戏名>`，云端目录与其它机种同构（`<平台>/<ROM SHA-256>/state/fceumm/` 与 `sav/`）。`--emulator` 有配对校验：`fceumm` 只能配 `FC`，mGBA/gpSP 不能用于 FC。
> 跨版本提醒：FC 单元需要 v0.0.44 及以上的设备才看得见；旧版本遇到云端 `FC/` 目录不会报错，只是不显示。

## 卡带集合的区分（槽内蚀刻）

每个卡带集合在底部插卡口里不再放独立铭牌，而是在槽底直接蚀刻：`最近游玩` / `收藏` / `GBA` / `GB` / `GBC` / `FC`，下面再刻全名。切换货架时跟着换。卡带插入后会被卡带盖住，不再显示机种，和上游 Slot 的 `slot_back_*.png` 是同一个位置和思路。

- 默认使用内置蚀刻字标（无底板、无边框，只有凹刻的暗/亮边），不依赖卡上美术；
  所有合集（GBA / GB / GBC / FC / SFC / 最近游玩 / 收藏）默认都使用同一套大字号，版本包不带默认铭牌图；
- 想换成自己的图，把 PNG 放到卡的 `System/linkSlot/assets/carts/` 下，文件名：
  `slot_back_recents.png`、`slot_back_favorites.png`、`slot_back_gba.png`、`slot_back_gb.png`、`slot_back_gbc.png`、`slot_back_fc.png`、`slot_back_sfc.png`；
- 图片会按比例放进插卡口，并**裁成插卡口的形状**（中间竖缝 + 拇指弧），所以原图不需要自己做遮罩；建议 380×44、透明底，只画刻字；
- 全屏的集合色氛围（GBA 淡蓝、GB 淡绿、GBC 淡紫、收藏淡黄+星星、最近游玩暖橙）仍然保留；槽内刻字本身保持中性钢灰色，避免再出现一层彩色标签。

## 主题

`M → 卡带架 → 外观与显示 → 主题`，按 A 进入主题列表，选择一套后按 A 应用：

- **默认深色**：原来的深灰 Switch 风格；

```text
preset web
```

`preset` 支持 `default` / `web` / `warm`，也接受旧版的四个卡槽颜色。旧文件不需要迁移；文件里的显式颜色仍会覆盖预设：

```text
preset warm
housing #3b2b20
```

## 屏幕遮罩（FC / GB / GBC / SFC）
`M → 画面 → 遮罩` 下有四行，分别给 FC、GB、GBC、SFC 选择屏幕贴图：

```text
FC 遮罩   Overlay/FC/*.png
GB 遮罩   Overlay/GB/*.png
GBC 遮罩  Overlay/GBC/*.png
SFC 遮罩  Overlay/SFC/*.png
```

每行**左右选择**「无」或对应目录下的任意 PNG（例如 `FC01.png`、`GB01.png`、`GBC01.png`、`SFC01.png`…，文件名直接显示在菜单行上）。选中后运行对应机种的游戏时，会把该图叠在游戏画面上（菜单与提示仍在最上层）。

- GBA 不支持屏幕遮罩；着色器与调色板不受影响。

## 长按 Y 的同步选择（mod 注册制）

带 `manual`（手动）动作的 mod（例如 GBAStation 电池存档同步、SaveDeck 电池存档桥、AI 游戏资料补全）**不再直接接管长按 Y**，而是向长按 Y 登记一个选项。满足任一条时，长按 Y 会先弹出卡片，左右选择后按 A 执行：

- 只有一个内置项「同步云存档」时（没有启用的手动 mod），长按 Y 不弹选择页，直接从游戏卡背后切出云卡；提前松手会切回游戏卡；
- 启用 1 个手动 mod → 2 个选择项：`同步云存档`、`同步 <mod 名称>`；
- 启用 2 个 → 3 个选择项，例如同时启用 SaveDeck 与 GBAStation：
  `同步云存档` / `同步 SaveDeck 电池存档桥` / `同步 GBAStation 电池存档同步`；
- ← / → 循环选择，A 开始，B 关闭；云同步仍遵循「网络设置 → 同步方式」的 `--only` 限制。

同一个 mod 有多个手动动作时会各占一张卡片，标签为 `同步 <mod 名称> · <动作名称>`。mod 的优先级（`mod.json` 的 `order`）只影响列表顺序，不再决定「谁抢到 Y」。设备「M → mod 设置」里可以看到、启停 mod。

选中 mod 后如果 mod 脚本自己发现冲突，会弹出**该 mod 自己的冲突页**（标题为 `<mod 名称> · <mod 给的标题>`，选项由 mod 提供）；确认后带着 `--choice` 重新运行**同一个 mod 动作**（`mods run --id … --action …`），不会退回云同步。云同步的冲突页与方向选择保持原样。

选择页恢复为 v0.6.11 的**联网卡带**：所有选项都是同一张固定 GBA 形状的深枪灰卡带，壳顶印「联网卡带」；贴纸写在卡带标签区域，云同步是「同步云存档」，mod 是 mod 名称。左右滚动选择，只有两个选项时到边缘会顶一下对话框。

云同步卡带使用内置云图标贴纸；mod 可以自带 `sticker.png`，没有时回退到同版式文字贴纸。选卡或长按自动取出后，联网卡带会先从游戏卡背后切到前面，再插入卡槽。

**启动卡带 / 云同步不受影响**；冲突页的「重试」始终走云同步，不会弹卡片。

## 云同步（linkSlot）

### manual mod 动画（0.6.6 起）

manual 动作可以在 `action.json` 里声明 `ui`，复用云同步动画的数据弧、卡带和云朵，但标题、单元和方向由 mod 自己声明：

```json
"ui": {
  "animation": "cloud_sync",
  "title": "同步电池存档",
  "units": ["sav"],
  "show_cloud": true,
  "direction": "upload"
}
```

- `units` 可为 `state` / `sav`，最多两个；
- `show_cloud` 可关闭右侧云朵；
- `direction` 可指定上传或下载；
- 没有 `ui` 的 manual mod 仍使用简洁暗幕，不显示云同步轨道。

### mod 界面 API（0.6.6 起）

manual Lua 动作可以显示基础弹窗：

```lua
local ok = ui.confirm{
  title = "继续？",
  body = "将同步当前存档。",
  yes = "继续",
  no = "停止",
}

ui.message{
  title = "提示",
  body = "同步完成。",
  button = "知道了",
}
```

- `ui.confirm` 返回布尔值；B 等同「否」；
- `ui.message` 是单按钮文字弹窗，关闭后返回 true；
- 两者复用 `mods.choose` 的可恢复检查点，首次调用会中止脚本并弹窗；
- 仅 manual 动作可用。

### 云存档同步动画（0.6.5 起）

云同步和声明了 ui 的 manual mod 共用同一套动画：

- 左侧当前卡带，右侧云端/目标；
- 上下两条数据弧，上传/下载方向相反；
- 中间一个「同步数据」通用标签，不再写 `STATE` / `SAV`；
- 底部是一条进度条，替代原来的五段节点轨道；
- 云同步按阶段推进（Net / Connect / Transfer / Verify / Commit），不显示伪造百分比；
- 完成时短暂显示勾选与云端版本，再进入结果横幅；
- 无更新只播放一次短云朵脉冲；
- manual mod 可以用 `mods.progress{value=0..1,label=...}` 上报真实百分比；没有上报时显示不定进度扫光；
- 没有声明 ui 的 manual mod 不播放这套动画；冲突/错误弹窗保持原样。

在主界面（卡带浏览）选中卡带后，**长按 Y 键约 1.5 秒**触发同步。有手动 mod 时会先弹出 v0.6.11 风格的**联网卡带**选择页：

1. 长按 Y，出现同一排联网卡带；云同步贴纸「同步云存档」，mod 贴纸写 mod 名称；
2. 选择云同步后，联网卡带从选择页缩小、插进主机卡槽；如果 WiFi 还没连上，也直接进入同步动画，在动画里等待连接；
3. 卡带坐好后，同步画面像普通游戏启动一样从屏幕中央展开：左侧游戏卡、右侧云朵、两条数据弧和中间一个「同步数据」标签；底部改为进度条；
4. 手动 mod 也先插入联网卡带，再启动 mod 动作；
5. 没有手动 mod 时，长按 Y 会让云卡从游戏卡背后切出；满 1.5 秒后自动插入，提前松手则切回游戏卡。

不再有 NET 转接卡槽、顶部夹扣或侧插卡片。冲突页仍会覆盖动画；确认方向后回到同一个云同步动画。

**云同步**：选择「同步云存档」并确认后，联网卡带插入卡槽，然后进入云同步动画；结束时画面向中央收拢，随后联网卡带从卡槽弹出，再显示结果。插入和弹出过程中卡槽本体保持可见；没有手动 mod 时由自动云卡完成同一段插入/弹出。短按 Y 没有功能；A 短按启动、A 长按约 0.5 秒从头启动、M 设置菜单等原有按键不变。

云同步本身：云端较新时自动拉取，本地较新时自动推送，一致时提示“已是最新”。短按 Y 没有功能；A 短按启动、A 长按约 0.5 秒从头启动、M 设置菜单等原有按键不变。


**游戏介绍**：在卡带架按住 B 约 0.5 秒打开介绍弹窗；弹窗不再重复显示游戏卡带标题，直接从介绍内容/封面开始。介绍文字超过一屏时，按方向键 ↓ 一行一行向下滚动、↑ 向上；右侧有滚动条。演示视频边解码边显示，不再等整段解码完才开始播放。文字放在 `Labels/<平台>/<游戏名>.txt`（UTF-8）；没有这个文件时显示“暂无游戏介绍”。封面仍取 `Labels/<平台>/<游戏名>.png`，按原图比例显示，不裁剪也不拉伸，多余区域留空。演示视频放 `Labels/<平台>/<游戏名>.mp4`：支持 H.264 视频轨（无音频），弹窗在后台低优先级解码、复用单张纹理播放；H.265 或解码失败时显示封面。关闭介绍页会释放视频纹理。短按 X 仍是检索。在介绍页按 **Y** 可删除当前卡带（页面底部使用与「B 返回」相同的按键样式显示「Y 删除卡带」），会先弹出「删除卡带 / 取消」二次确认；删除 ROM、封面、介绍、视频和数据库元数据，保留 Saves/States 中的存档与进度。

## 天马G 游戏信息导入

配套 mod「天马G GBA 游戏信息导入」只导入介绍、封面和演示视频，不复制 ROM、不碰存档。

1. 把天马G 的 `Roms` 目录复制到卡内 `Imports/TianmaG/`；
2. 在 Web 的 Mods 页面打开这个 mod，确认路径后开始导入。

匹配使用项目现有的 **FNV-1a 64 位 ROM hash**：解压天马包里的 ROM zip，计算内部 `.gba` 的 hash，再和卡内 `Games/GBA` 的未压缩 ROM 精确匹配。匹配到后写：

- `Labels/GBA/<游戏名>.txt`：`description`；
- `Labels/GBA/<游戏名>.mp4`：`media/<游戏名>/video.mp4`；
- `Labels/GBA/<游戏名>.png`：仅当本地没有封面时写入 `boxfront`。

已有介绍/视频默认跳过，可在 mod 页面选择覆盖；已有封面始终跳过。整合包约 5.7GB，首次哈希需要较长时间，页面有进度和取消。

### Web 游戏库合集导入/导出

「游戏库」页新增「导入合集」和「导出合集」：

- 先在平台筛选里选中一个集合，例如 GBA，「导出合集」会生成
  `Exports/linkslot-gba-<时间戳>.zip`；
- 包内包含该平台所有 ROM，以及同名封面 `.png`、介绍 `.txt` 和演示视频 `.mp4`；
- 导出在后台进行，完成后页面给出下载链接；大合集通过流式下载，不再受 64MB 下载上限限制；
- 「导入合集」上传同格式 ZIP，自动解压 ROM 和 Labels；同名文件会覆盖，存档不包含也不受影响；
- 导入支持大文件分片上传（每片 8MB），无需把整个合集读进设备内存。

合集清单为 ZIP 根目录的 `linkSlot-collection.json`，只包含本机格式，不兼容天马G 原始包（天马包请用对应 mod 导入）。

### Web 上传游戏介绍与视频

Web 的「游戏库」→ 点开游戏卡片 →「游戏详情」里新增：

- **上传 .txt**：作为当前游戏的介绍，自动保存为 `Labels/<平台>/<ROM 文件名>.txt`；
- **上传 .mp4**：作为当前游戏的演示视频，自动保存为 `Labels/<平台>/<ROM 文件名>.mp4`；只接受 MP4 容器，播放端要求 H.264。

上传时会忽略原文件名，只用当前 ROM 的名字绑定；介绍限 256KB、UTF-8，视频限 32MB。设备不处于游戏/同步状态时才允许写入。

**ROM 身份**：同步单元按 ROM 文件的完整 SHA-256 识别，不再按游戏名识别。云端目录形如 `<remote_root>/<平台>/<模拟器>/<64位SHA-256>/`（例如 `linkSlot/GBA/mgba/6f1c…`），`meta.json` 的 `unit` 也带 `rom_sha256`；游戏名只用于本地 `States/<平台>/<模拟器>/<游戏名>` 目录和界面显示。因此同一个 ROM 改名后，hash 不变，会被识别为同一份云端存档；改名的第一次同步会把云端存档拉回新名字的本地目录（本地尚未同步的旧名字目录不会自动搬迁）。
**旧数据不自动迁移**：旧版本按游戏名建立的云端目录不会被新客户端读取、移动或删除；如需继续使用，可在电脑上计算对应 ROM 的 SHA-256，把云端旧目录改名为这个 hash（下一次推送会补写 `rom_sha256`）。不同内容的同名 ROM 会得到不同 hash，互不覆盖；同一目录下若存在多个同名 ROM 自动发现会报错，手动 CLI 可用 `--rom` 指定。

首次使用：

1. 在电脑上编辑卡内 `linkSlot/Config/config.toml`（可用 `sh System/linkSlot/shell/linkslot.sh config init` 生成模板），填写 WebDAV 的 `url`、`username`、`password`（建议密码留空、改用环境变量），可选填写 `[wifi]` 的 `ssid`/`psk` 让 linkSlot 在同步时按需联网；WiFi 也可以在设备「网络设置 → WiFi 连接」里配置。
2. 如果 NAS 使用自签证书，把 PEM 路径填到 `[webdav] ca_cert`；设备时钟必须正确，否则 HTTPS 会报证书/时钟错误。
3. 手动 CLI 运行 sync/push/pull/status 时，`--rom <ROM 路径>` 可显式指定 ROM；省略时 linkSlot 会在 `Games/<平台>` 下按 `--game` 自动查找唯一同名 ROM，找不到或有多个同名 ROM 时会报错并提示使用 `--rom`。

行为说明：

- **卡带界面状态栏**：顶部状态栏左侧显示时间，右侧显示 WiFi 连接状态与电池电量；底部左侧提示“长按 Y 同步 / X 检索”，右侧提示“长按 B 查看游戏介绍”。WiFi 图标变暗表示当前未连接（同步时会按需联网）。
- **智能同步**：`sync` 先读云端 `meta.json`，按版本号 + 哈希自动判断方向；同步中播放卡带与云之间的传输动画，按 B 可取消（本地/云端不会被写坏），超过 120 秒自动取消。
- **差量传输**：方向确定后只传输与云端 `meta.json` 记录不一致的文件（逐文件比对 SHA-256）。例如玩过后新增一个即时存档，通常只传 `resume.state` + 新档 + 缩略图（约 1MB），不再重传整单元（约 5MB）；未变化的文件不重新上传/下载。
- **推送**：先写盘，再上传本游戏变化的 `resume.state` + 时间戳存档及缩略图；失败或冲突不会改动本地文件。
- **拉取**：只下载变化的文件，校验后原子替换本地存档；未变化的本地文件原样保留；新 `resume.state` 在**下次插卡启动**时生效。
- **全量修复**：手动命令可加 `--full`。`push --full` / `pull --full` 会忽略“已是最新”判定，强制整单元重传/重下，用于修复被其它工具删改的云端或本地文件；`pull --full` 会覆盖本地未推送修改，覆盖前先按冲突规则备份为 `<游戏名>.conflict.<时间>/`。`sync --full` 只在判定需要传输时忽略差量。UI 长按 Y 的智能同步始终走差量。
- **冲突**：不会自动覆盖。卡带外框变红，显示云端/本地版本、设备与时间；左右键选择“覆盖云端/覆盖本地”（默认覆盖本地），A 确认后进入同步动画，B 取消且不修改文件。覆盖前自动备份被覆盖方：拉取覆盖本地时备份为 `<游戏名>.conflict.<时间>/`；上传覆盖云端时备份云端旧 meta.json 与旧状态文件。
- 只同步状态存档，不同步 `.sav` 电池存档；不后台自动同步；联机进行中不能同步；同步期间不要关机/重启（会先取消同步）。
- 已知限制：只有 1 个 ROM 的卡开机会直接进入游戏且不能退卡，因此暂时无法使用主界面长按 Y 同步（多 ROM 卡正常）。本地 States 目录仍按游戏名；如果两个不同 ROM 使用同一个文件名，它们会共用同一个本地状态目录（建议保持文件名唯一）。
- 日志在 `linkSlot/Logs/linkSlot.log`，可用 `adb pull` 取回；配置在 `linkSlot/Config/config.toml`，不在覆盖范围内。

## R13：网络设置与 Web 管理

主界面按 M → 网络设置，二级菜单为「WiFi 连接」「启动 Web 服务」。

### WiFi 连接
- 打开后先读取实际 WiFi 状态，页面顶部有 WiFi 开关：开关关闭时不扫描，打开后才开始扫描（Y 刷新）；上下选择，A 连接。关闭开关会断开当前 WiFi 并停止扫描；linkSlot 云同步的按需联网仍可能在同步时重新打开 WiFi。页面里的「自动关闭 WiFi」可设置 5/10/30/60/120 分钟或永不（默认 10 分钟）。
- 开放网络直接连接，加密网络会弹出屏幕键盘输入密码：A 输入、B 删除、Y 切换大小写/数字符号页、START 确定、X 取消。英文键盘与数字键盘一致为 5×10 矩形布局。也可以选「手动输入网络名称」连接隐藏网络。
- 连接成功后凭据写入 `linkSlot/Config/config.toml` 的 `[wifi]`（`manage = true`、`ssid`、`psk`），linkSlot 云同步与设备重启后按需联网都会复用同一份配置；不再需要只在电脑上改卡。
- 设备键盘只支持 ASCII；SSID 含中文时请在电脑/手机 Web 页面填写。连接失败会显示脚本返回的错误摘要，可重试。
- 状态栏 WiFi 图标表示 `wlan0` 有载波且取得可用 IPv4，**不表示云端 WebDAV 主机可达**；NAS/电脑休眠或地址错误时同步会失败，结果条会显示具体原因（例如“无法连接 WebDAV 主机 192.168.x.x:15000”），完整记录在 `linkSlot/Logs/linkSlot.log`。

### 启动 Web 服务
- 点击后先检查 WiFi 是否已连接并取得 IP；未连接时弹窗提示先连接 WiFi（不会自动开热点）。
- 成功后在 8080–8089 中选一个空闲端口启动 HTTP 服务，弹窗显示访问地址，例如 `http://192.168.3.8:8080`。**关闭弹窗（B/M/A）即停止服务**；设备休眠、关机、重启时也会自动停止。
- 手机/电脑与设备在同一局域网时，用浏览器打开该地址即可进入 Web 管理页（深色青绿风格，来自 SaveContinue 参考；所有页面与图标内嵌，无外网依赖）：
  - **概览**：Slot/linkSlot 版本、WiFi SSID 与 IP、访问地址、即时存档/电池存档数量、所有游戏跨设备累计总时长、可写状态、最近日志。
  - **存档**：按平台/模拟器/游戏列出即时存档（缩略图、时间、续玩档）与电池存档（`.sav`/`.srm`），支持逐个下载与上传覆盖；每个游戏显示跨设备累计游戏时长；上传前请确认文件名与目标位置。
  - **云同步**：查看/修改 WebDAV 配置（密码留空表示不修改），查看每个同步单元的缓存版本与时间，按单元「立即同步」；同步同样按 ROM 的 SHA-256 识别，网页显示的游戏名不影响云端匹配；冲突仍回设备卡带界面处理。保存的是同一份 `linkSlot/Config/config.toml`。ROM 改名后请先在设备端用新名字卡带同步一次；Web 上遗留的旧名字存档目录如果找不到同名 ROM，点同步会报“未找到 ROM”。
  - **网络**：查看当前 WiFi、扫描并连接其他网络（切换网络会短暂断开当前网页）。
  - **文件**：浏览卡内目录；下载 `Logs/` 下的日志时会自动改名为「日志名_设备型号_日期.log」，例如 `linkslot_rg34xx_20261029.log`，方便区分两台设备、不同日期的日志。
  - **关于**：版本与说明；「一键导出日志」把 `Logs/`（含 `crash/` 崩溃记录）与 `version.json` 打成 zip，文件名带设备型号与本地时间，例如 `rg34xx_20261029223000_log.zip`，便于发回分析。程序上次若是崩溃/异常退出，启动时日志会写一条 `previous run ended unexpectedly (cart=…, linked=…)`，可直接连同这份打包发回。
- 安全边界：Web 服务无登录、仅监听局域网、无外部依赖，请只在可信网络使用；局域网内任何能访问设备 IP 的人都能查看/上传存档。所有写操作要求自定义请求头 `X-Slot-Web: 1`，可降低其他网页误触的风险，但不是完整鉴权。
- 游戏中或同步进行中时 Web 端写操作会被拒绝（409），只读查看仍可用；开启 Web 服务后设备保持菜单界面，建议完成操作后关闭弹窗。
- 只允许读写 `States/`、`Saves/` 下的白名单扩展名，路径穿越与符号链接逃逸会被拒绝；上传采用临时文件 + 原子替换。

更新包需包含 `System/linkSlot`、`System/linkSlot/shell/linkslot.sh`、`System/linkSlot/shell/linkslot-net.sh`、`System/linkSlot/shell/slot-wifi.sh` 四个文件；Web 页面已编译进 `System/slot`，不需要单独复制网页文件。

## R15：WiFi 闲置自动关闭

- WiFi 页新增「自动关闭 WiFi」设置：5 分钟 / 10 分钟 / 30 分钟 / 1 小时 / 2 小时 / 永不，默认 10 分钟；设置写入 `linkSlot/Config/config.toml` 的 `[wifi] auto_off_minutes`，重启保留，`0` 表示永不。

## 在浏览器里游玩 GBA

游戏详情里点「在浏览器游玩」，会新开一个标签页（`/play?rom=Games/GBA/<游戏>.gba`）：

- 模拟器（mGBA 的 WebAssembly 版）跑在浏览器里，设备只负责把 ROM 和 `.sav` 传过去，不占设备 CPU；
- 首次进入要下载 ROM（16 MB 局域网约 3–8 秒），模拟器核心文件会缓存一天；
- 电池存档全自动：进入时从 `Saves/GBA/<游戏>.sav` 读取，暂停、退出、切后台以及每 5 分钟自动写回；
  写回前旧存档会备份成 `.sav.bak`，如果设备上的存档在浏览器打开后被改过，会拒绝写回并在顶栏提示；
- 浏览器和掌机不要同时玩同一个游戏；
- 目前支持 GBA（mGBA 核心）、GB/GBC（Gambatte 核心）和 FC（FCEUmm 核心）；
- FC 可开「双人同屏」：P1 为 `W/A/S/D` 移动 + `J/K/L`（J=B、K=A、L=连发 A，`U/I` 为 Select/Start）；
  P2 为方向键移动 + 数字键 `1/2`（B/A）、`3/4`（连发 A/B）、`5/6`（Select/Start）；
- 手柄：先连接的手柄是 1P，第二个手柄在双人模式下自动成为 2P；单手柄时只控制 1P；
  输入面板会显示当前识别到几个手柄；手机端虚拟手柄只对应 1P。
